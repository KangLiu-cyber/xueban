# 学伴 × 体育教育：系统思维应用方案

面向决策者与研发。本文先提炼学伴的系统思维，再说明这套思维如何落地到体育教育（教学视频提取纪录、笔记富媒体存储、AI 分析学习问题与改进）。

## 一、学伴的系统思维（先讲思维）

学伴做得对的核心不是某个具体功能，而是一套可复用的思维，共五条：

1. **内容由 AI 生成，平台只做存储与交互**——用户提供原始素材（课程视频），Agent 生成结构化内容（目录、笔记、要点、习题），平台负责存储、展示与交互。AI 生成能力在 Agent 侧运行，服务端零推理成本。
2. **闭环不中断**——看课 → 出笔记 → 练习 → 错题归集 → 复盘诊断 → 补强写回，每一步产生的数据驱动下一步，环环相扣。
3. **数据分两层**——原始数据（AI 生成的内容）与派生数据（使用过程记录：作答、错题、事件流）。复盘 = 读派生数据 → 诊断 → 写回新的原始数据。
4. **生成能力以 Skill 形式下发**——系统不绑定任何生成能力，Agent 接入时按「Skill + 提示词 + 工具清单」装配，服务端升级即自动下发新版。换领域 = 换一套 Skill，不动系统。
5. **一套通用模型承载一切「内容 + 练习 + 复盘」场景**——内容树自由嵌套、题库按集归属、事件流记录一切行为。换领域时只加内容类型与 Skill，不重写系统。

## 二、体育教育的需求映射

老板提出的三个需求，逐一映射到学伴思维：

### 1. 教学视频提取纪录（对标「看课 → 出笔记」）

| 备考场景 | 体育教育场景 |
|:---|:---|
| 课程视频 → AI 生成每集笔记 | 教学视频 → AI 生成动作要领笔记（技术要点、分解步骤、常见错误、训练提示） |
| AI 批注（老师强调、考点标注） | AI 批注（教练强调、易错点标注） |
| 每集习题（带答案与解析） | 每集「要领检验」（动作顺序判断、要领问答、规则判断，带解析） |

示例：一段「三步上篮」教学视频 → Agent 生成笔记：

- 技术要点卡片：持球、起跳、出手各阶段要领；
- 分解步骤与图示（配图或关键动作片段）；
- 常见错误与纠正提示；
- 5 道要领检验题，如「三步上篮第二步落地时哪只脚在前？」——答错即自动归集，定位到具体技术环节。

### 2. 笔记富媒体：图片 + 视频（对标「附件」）

现状：系统已支持笔记内嵌图片附件（png/jpeg/gif/webp，单文件 ≤10MB，Agent 上传、客户端带鉴权渲染）。

体育教学需要视频，属**既有扩展点上的增量**：

- 教学视频原片：Agent 提取的关键动作片段（短 gif/webp 现成支持；长片段用 mp4/webm）；
- 用户自己的训练录像与图片：可上传，供 AI 复盘分析（对标个人批注，来源标注 user）；
- 需要扩展的能力见第三节清单。

### 3. AI 分析学习问题、改进（对标「复盘诊断」）

体育训练天然产生过程数据，比备考更适合 AI 复盘：

- **训练打卡**：每次训练记录内容、完成度、自评（如「三步上篮命中 7/10」）；
- **要领检验作答**：检验题答错 = 哪个技术环节没理解；
- **训练录像（可选，进阶）**：用户上传录像，Agent 分析动作是否到位。

复盘闭环与备考一致：Agent 读取训练记录与检验作答 → 诊断薄弱点（如「起跳环节理解错误、三步节奏不稳」）→ 生成改进方案写回系统：

- 针对性知识点：纠正动作的讲解笔记（含图示/视频片段）；
- 个性化训练计划：本周练什么、怎么练、练几次；
- 新的要领检验题，供下一轮训练检验。

## 三、需要的能力增量（对现有系统的扩展清单）

| 能力 | 现状 | 增量 |
|:---|:---|:---|
| 视频附件 | 仅图片（png/jpeg/gif/webp，≤10MB） | MIME 白名单增加 mp4/webm；大文件上传（分片或提高上限）；前端视频播放组件；安卓端同步支持 |
| 内容类型 | dir / note | 新增训练记录类型（打卡），或复用 note + 约定字段 |
| 事件类型 | annotate / answer / wrong / agent_write | 新增训练打卡、自评事件，供复盘 Agent 读取 |
| Skill 目录 | 通用学习 Skill | 新增体育 Skill 包：教学视频 → 动作笔记、要领检验生成、训练计划、问题诊断 |
| 训练数据 | 无运动数据接入 | 第一阶段靠打卡与自评；后续可接入可穿戴设备/录像分析，作为 Agent 的数据源 |

要点：以上增量全部落在既有扩展点上——内容树、题库、事件流、Skill 目录本就为扩展而设计，**不改架构，只加类型与 Skill**。

## 四、落地路径（最小闭环先行）

- **阶段一 · 最小闭环**：教学视频 → Agent 生成动作要领笔记（含图片/视频片段 + 要领检验题）→ 用户看笔记看视频 → 刷检验题、答错自动归集 → 训练打卡记录。
- **阶段二 · AI 诊断改进**：Agent 读取训练打卡 + 检验错题 → 生成个性化改进方案（纠正笔记 + 训练计划 + 新检验题）→ 写回系统 → 下一轮训练，闭环运转。
- **阶段三 · 进阶（可选）**：训练录像上传 → Agent 动作分析（配合图片/视频批注）→ 更精确的问题定位。

## 五、与备考版的关系

- 同一套后端、同一套账号体系、同一套 Agent 接入——体育教育作为新的**领域包**（内容类型 + Skill 集 + 前端领域页面）挂载到学伴系统上，不重复建设；
- 前端按既有原型规范扩展（桌面端 v3 柔和版、安卓端 v1 规范）；
- 商业化上可与备考版合并订阅或单独定价，由现成账号体系支撑。

## 六、建议的下一步

1. 确认体育领域范围（目标人群、项目：球类/田径/健身等，先选 1~2 个试点项目）；
2. 输出体育版需求文档（对标 `requirements.md`），把本节「能力增量」固化为需求条目；
3. 视频附件与视频播放能力优先排期（它是两个闭环的地基）；
4. 编写体育 Skill 包并在现有 Agent 接入链路中验证「教学视频 → 动作笔记 → 要领检验」最小闭环。
