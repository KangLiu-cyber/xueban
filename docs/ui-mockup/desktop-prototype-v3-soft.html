软件架构风格

本集框架

本集讲解五大经典架构风格的核心思想、适用场景与对比。重点掌握数据流风格、调用返回风格、独立构件风格、虚拟机风格和仓库风格的特征区分。

知识卡片

★ 数据流风格

★批处理：数据整体传递，适合大规模数据处理。老师强调：批处理与管道的区别在于数据传递粒度批处理是整体传递，管道是流式传递

★管道-过滤器：数据流式传递，每个过滤器独立处理，支持并行。典型应用：编译器四阶段。

调用返回风格

主程序-子程序：面向过程，层次清晰。面向对象：封装继承多态，适用于需求变化频繁的系统。

★层次结构：每层只与相邻层交互，典型如 OSI 七层模型、TCP/IP 四层模型。考点：层次结构的最大优点是可扩展性和可移植性层次结构支持跨层透明，方便替换实现

独立构件风格

进程通信：构件间通过消息传递交互，松耦合。

★事件驱动：构件通过事件订阅/发布解耦。典型应用：GUI 框架、消息队列。老师补充：事件驱动 vs 观察者模式的区别事件驱动更宏观，观察者模式是事件驱动的一种实现

虚拟机与仓库风格

解释器：解释执行非原生代码，灵活但性能低。典型：JVM、Python 解释器。基于规则的系统：用规则引擎驱动业务逻辑，适合专家系统。

★黑板系统：中央黑板 + 多知识源 + 控制器，适合不确定性高的问题。考点：黑板架构的三要素黑板(共享数据) + 知识源(独立构件) + 控制器(调度)

速查表

风格核心特征典型应用
批处理整体数据传递ETL、数据清洗
管道-过滤器流式传递、可并行编译器
层次结构相邻层交互OSI、TCP/IP
事件驱动发布/订阅解耦GUI、MQ
黑板中央黑板+知识源语音识别、专家系统

考试提示

★常考判断题：管道-过滤器风格是否支持并行？答：支持，各过滤器可并行执行。
★常考选择题：以下哪种风格最适合不确定性高的问题求解？答：黑板架构。
★易错点：解释器是运行时翻译，编译器是提前翻译。编译器的管道-过滤器风格是编译过程本身的架构，不要混淆。

在管道-过滤器架构风格中，以下哪项是其最显著的特征？
A
构件间通过共享变量进行通信
B
数据以流的方式在过滤器间传递，支持并行处理
C
通过事件发布和订阅实现构件解耦
D
使用中央黑板共享数据并由控制器调度
✓ 答对了 · 解析
管道-过滤器风格的核心特征是数据以流的方式在过滤器之间传递，每个过滤器独立处理输入并产生输出，因此天然支持并行处理。选项A描述的是仓库风格，选项C描述的是事件驱动风格，选项D描述的是黑板架构风格。
