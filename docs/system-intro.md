# 学伴 · 超级学习助手 — 系统介绍

面向管理层与决策者。本文展示学伴的产品定位、核心能力与差异化价值；技术细节见 `architecture.md`，需求定义见 `requirements.md`。

## 一、一句话定位

学伴不是又一个笔记软件，而是以**智能体为核心**的超级学习助手：把「看课 → 出笔记 → 刷题 → 复盘补弱」的完整学习过程自动化——AI 替用户整理知识，平台帮用户练习巩固，AI 再帮用户诊断改进，形成环环相扣的学习闭环。

## 二、产品亮点

### 1. 完整的学习闭环，一步不落

看课 → AI 自动生成笔记与批注 → 刷题即时判分 → 错题自动归集 → 组卷模考 → AI 复盘诊断 → 针对性补强写回系统。七个环节全部打通，每一步产生的数据驱动下一步。

### 2. 智能体驱动的生成架构——服务端零 AI 推理成本

所有 AI 生成能力（目录、笔记、批注、习题、复盘）由用户自己的 Agent（TRAE 等任意主流产品）承载，通过 MCP 协议接入本系统。本服务端**不做任何 LLM 推理**，只做存储、展示与交互。

- **成本优势**：服务器成本与用户量近似线性于存储与带宽，不受 AI 推理成本牵制。
- **质量优势**：生成质量跟随 Agent 生态持续升级，不锁死单一厂商；用户用自己的账号接入，无需为 AI 能力额外付费。

### 3. 一套代码，三端覆盖

前端用 Rust（Leptos）编译 WASM，**网页端与桌面端（Tauri）共用同一套 UI**；安卓端（Kotlin + Compose）独立实现，支持折叠屏双栏适配。三端共用同一后端 API，不重复建设。

### 4. 数据安全与严格隔离

每用户独立 token，Agent 只能以该用户身份读写该用户的数据，协议层杜绝串数据；账号体系为订阅计费预留基础。

### 5. 通用架构，可横向扩展

内容树自由嵌套、题库按集归属、事件流记录一切行为——这套「内容 + 练习 + 复盘」的通用模型，可以承载任意学习领域，不止考试备考。**向体育教育等新领域扩展，换的是内容类型与 Skill 集，不是系统本身**（见《体育教育方向方案》）。

## 三、系统怎么工作

```
任意 Agent（生成目录/笔记/批注/习题，复盘分析）
      ▲ ▼ 凭证接入 → 服务下发 Skill + 提示词 + MCP
本系统（多用户：存储 + 展示 + 交互，数据按用户隔离）
```

系统分两个平面：

- **智能体平面**：用户自己的 Agent，负责全部生成与分析；
- **展示交互平面**（本系统）：账号、内容存储、展示与交互——批注、刷题、判分、错题、组卷。

### 用户视角的完整流程

1. 注册登录，填写考试目标与日期，考试倒计时自动开启；
2. 复制一段接入凭证，交给任意 Agent（如 TRAE），一次接入，长期有效；
3. 对 Agent 说「帮我学第 3 集」——Agent 自动生成目录、笔记、AI 批注与每集习题；
4. 用户看笔记（可加个人批注）、刷题（即时判分），答错自动进错题本；
5. 学完一章发起复盘——Agent 读取错题与答题行为，诊断薄弱点，生成补充知识点与针对性习题写回系统，闭环再启动。

### 数据思维：原始数据与派生数据

- **原始数据**（AI 生成）：目录、笔记、批注、习题；
- **派生数据**（使用过程产生）：刷题记录、错题本、组卷模考、个人批注；
- **复盘** = Agent 读派生数据 → 诊断 → 写回新的原始数据。

AI 生成是唯一的原始数据源，刷题、错题本、组卷都是使用过程中的派生数据——这也是成本可控与闭环成立的根基。

## 四、技术含金量

| 层 | 选型                                                          |
|:---|:------------------------------------------------------------|
| 后端 | Rust（Axum + SQLx）+ PostgreSQL 16，六边形架构 + DDD，单二进制部署         |
| 前端 | Rust（Leptos）编译 WASM，一套代码双形态（网页 + Tauri 桌面）                  |
| 安卓端 | Kotlin + Jetpack Compose + Material 3，WindowSizeClass 折叠屏适配 |
| Agent 接入 | MCP over HTTPS，能力包（Skill + 提示词 + 工具清单）版本化管理，服务端升级自动下发       |
| 部署 | Docker Compose 单机起步（2C4G 支撑数千日活），镜像不编译、宿主挂载即更新              |
| 成本模型 | 服务端零推理，单用户日均服务端几乎无成本                                        |

## 五、当前进展与路线图

- 需求 v7.2、架构 v1.1 定稿；桌面端 v3 柔和版原型、安卓端 v1 原型定稿；
- P0 账号与接入：注册登录、token、MCP 接入与能力下发、内容树写入（桌面端随 P0/P1 同步实现）；
- P1 学习闭环：批注、题库写入、刷题、错题本；
- P2 模考与复盘：组卷、模考判分、复盘事件读取、学习统计；
- P3 商业化基础：订阅计费接口、配额管理（按用户指示暂缓）。

## 六、商业价值与扩展空间

- 账号体系已按订阅计费设计（注册/登录/token 就位），商业化通道已铺好；
- 学习闭环模型可复制到任何「视频课程 + 练习 + 复盘」型领域——体育教育、职业技能培训、语言学习等，每个领域作为一组「内容类型 + Skill 集」挂载到同一系统上。
