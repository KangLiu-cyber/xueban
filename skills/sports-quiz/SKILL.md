# 体育笔记 → 检验题生成（刷题）

基于已生成的「动作要领笔记」，提取发力点、技术要点、常见错误、训练安排，生成检验题并写入学伴题库，进入刷题 / 错题本闭环。

## 触发场景
- 用户要求"基于笔记出题 / 生成习题 / 出检验题 / 刷题"，且已有动作要领笔记
- 用户说"用体育出题 skill"或类似表述

## 核心原则
1. **题目必须来自笔记**：题干与解析都依据笔记正文，不掺入网络知识或模型主观知识；笔记未覆盖的要点标注"（建议先补笔记）"。
2. **语言一致**：输出语言与用户最新输入一致。
3. **题量**：单篇笔记 5~10 道；用户指定薄弱环节（如"发力点"）时，针对性 3~5 道。
4. **解析必写**：每题写清"为什么对、为什么错"，判断依据落在笔记的具体段落。

## 读笔记
先定位题源笔记：
- `list_items(workspace_id)` 浏览树，找到目标笔记 id；或 `read_item(item_id)` 直接读正文
- 拿到 `workspace_id`（空间）与 `source_item_id`（笔记/集 id），出题必须挂到笔记下

## 出题结构（按题型分布）
| 类型 | 占比 | 示例 |
|:---|:---|:---|
| 技术要点 / 发力点 | 60% | "正手高远球发力顺序正确的是？" "手腕内旋闪动发生在哪个阶段？" |
| 常见错误识别 | 30% | "下列哪个是正手高远球常见错误？" |
| 训练安排 | 10% | "徒手挥拍建议每组多少次？" |

## 题目格式（与 save_questions 一致）
```json
{
  "qtype": "single",            // single | multi | judge
  "stem": "正手高远球发力顺序正确的是？",
  "options": ["蹬地转髋→转肩→挥臂→手腕内旋", "先挥臂再转髋", "只靠手腕发力", "只靠大臂发力"],
  "answer": 0,                  // single：正确选项下标（0 起）；multi：[下标...]；judge：true/false
  "explanation": "发力由下到上：蹬地转髋 → 转肩 → 大臂带动小臂 → 手腕内旋闪动，选项 0 正确。"
}
```
- `single` 的 `answer` 是**正确选项下标（0 起）**，`options` 通常 3~4 个
- `multi` 的 `answer` 是**正确下标数组**（如 `[0, 2]`）
- `judge` 无 `options`，`answer` 为 `true` / `false`
- 判断题注意表述歧义（"手腕" vs "小臂"），题干写具体

## 存题
```text
save_questions(workspace_id, source_item_id, questions[])
```
单批 ≤ 200 道。写入后题目自动进入该笔记的刷题与错题闭环。

## 常见问题
- **笔记没覆盖到考点**：不要编造，标注该题依赖"补充笔记"并提示先用 sports-video-notes 补全对应段落。
- **判断题答案有歧义**：把含混词替换成可验证的表述，解析里写明判断依据。
- **同一考点重复出题**：优先保证考点覆盖，避免同一知识点换皮多题。
